## 2. notification_logsテーブルの作成

### 2.1 Supabase SQL Editorで実行
`docs/design/06_notification_logs作成SQL.md` の内容を実行

```sql
CREATE TABLE IF NOT EXISTS notification_logs (
  id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
  user_id UUID NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE,
  profile_id UUID REFERENCES profiles(id) ON DELETE CASCADE,
  notification_type VARCHAR(50) NOT NULL,
  sent_at TIMESTAMP NOT NULL DEFAULT now(),
  created_at TIMESTAMP NOT NULL DEFAULT now()
);

CREATE INDEX IF NOT EXISTS idx_notification_logs_user_id ON notification_logs(user_id);
CREATE INDEX IF NOT EXISTS idx_notification_logs_profile_id ON notification_logs(profile_id);
CREATE INDEX IF NOT EXISTS idx_notification_logs_type ON notification_logs(notification_type);

ALTER TABLE notification_logs ENABLE ROW LEVEL SECURITY;

CREATE POLICY "Users can view own logs" ON notification_logs
  FOR SELECT USING (auth.uid() = user_id);

CREATE POLICY "Service role can manage all logs" ON notification_logs
  FOR ALL 
  TO service_role
  USING (true)
  WITH CHECK (true);
```

## 4. Cronジョブの設定

### 4.1 Supabase Dashboardで設定
1. Database → Cron Jobs を開く
2. 「Create a new cron job」をクリック
3. 以下を設定:
   - Name: `daily-notifications`
   - Schedule: `0 11 * * *` (日本時間20:00 = UTC 11:00)
   - Command:
   ```sql
   SELECT
     net.http_post(
       url:='https://YOUR_PROJECT_ID.supabase.co/functions/v1/send-daily-notifications',
       headers:='{"Content-Type": "application/json", "Authorization": "Bearer YOUR_ANON_KEY"}'::jsonb
     ) as request_id;
   ```

### 4.2 pg_cronの有効化
SQL Editorで実行:
```sql
CREATE EXTENSION IF NOT EXISTS pg_cron;
```

## 6. 通知ログの確認

### 6.1 送信履歴の確認
```sql
SELECT 
  nl.notification_type,
  nl.sent_at,
  p.name as profile_name,
  u.email as user_email
FROM notification_logs nl
LEFT JOIN profiles p ON nl.profile_id = p.id
LEFT JOIN auth.users u ON nl.user_id = u.id
ORDER BY nl.sent_at DESC
LIMIT 20;
```

### 6.2 通知タイプ別集計
```sql
SELECT 
  notification_type,
  COUNT(*) as count,
  DATE(sent_at) as date
FROM notification_logs
GROUP BY notification_type, DATE(sent_at)
ORDER BY date DESC, notification_type;
```

## 7. トラブルシューティング

### 7.1 Edge Functionが実行されない
**確認項目:**
- Cronジョブが正しく設定されているか
- URLとAPIキーが正しいか
- pg_cron拡張が有効か

**確認方法:**
```sql
SELECT * FROM cron.job;
SELECT * FROM cron.job_run_details ORDER BY start_time DESC LIMIT 10;
```

### 7.2 LINE通知が届かない
**確認項目:**
- line_notify_tokenが正しいか
- line_notify_enabledがtrueか
- LINE Notifyのトークンが有効か

**確認方法:**
```sql
SELECT user_id, line_notify_enabled, 
       CASE WHEN line_notify_token IS NULL THEN 'NULL' ELSE 'SET' END as token_status
FROM user_settings;
```

### 7.3 通知が重複する
**原因:** Cronジョブが複数回実行されている

**対応:**
```sql
-- 重複したCronジョブを削除
SELECT cron.unschedule('daily-notifications');
```

## 8. 運用

### 8.1 通知時刻の変更
user_settingsテーブルのnotification_timeカラムで個別設定可能（将来実装予定）

現在は全ユーザー一律20:00（UTC 11:00）

### 8.2 通知の一時停止
```sql
-- 特定ユーザーの通知を無効化
UPDATE user_settings
SET line_notify_enabled = false
WHERE user_id = 'USER_ID';
```

### 8.3 ログのクリーンアップ
```sql
-- 30日以上前のログを削除
DELETE FROM notification_logs
WHERE sent_at < CURRENT_DATE - INTERVAL '30 days';
```
